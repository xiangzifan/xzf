## 2. TUGR-Full 的三个相互关联改动

### 2.1 DUA 判别效用

设当前 mini-batch 包含 $B$ 个 query，query $q_i$ 对应的第 $j$ 个
目标模态 support 为 $v_{ij}$。首先计算：

$$
c_{r,ij}=\cos(q_r,v_{ij}).
$$

正项是当前 query 与其 support 的相似度：

$$
c_{i,ij}=\cos(q_i,v_{ij}).
$$

其他 query 对该 support 的吸引力为：

$$
n_{ij}
=
T\left[
\operatorname{LogSumExp}_{r\ne i}
\left(\frac{c_{r,ij}}{T}\right)
-\log(B-1)
\right].
$$

最终效用为：

$$
u_{ij}=c_{i,ij}-n_{ij}.
$$

因此，一个 support 只有在“匹配当前 query，同时不普遍吸引其他 query”时
才具有较高效用。代码使用一次矩阵乘法生成 $B\times B\times K$ 相似度，
避免 Python 循环。若 batch size 为 1，则安全退化为正余弦相似度。

默认对 $u_{ij}$ 使用 `detach`。这意味着模型不能通过扭曲路由分数走捷径，
但 GraphRefiner 的 value、残差和输出仍然正常接收检索损失梯度。

### 2.2 QDMP 查询条件化消息传递

原 GraphRefiner 的第 $h$ 个头只计算 support 间的注意力：

$$
e_{i,jr}^{(h)}
=
\frac{
(W_Q^{(h)}v_{ij})^\top(W_K^{(h)}v_{ir})
}{\sqrt{d_h}}.
$$

TUGR 先在每个 query 的 $K$ 个 support 内标准化效用：

$$
\widehat u_{ir}
=
\frac{u_{ir}-\bar u_i}
{\sqrt{\operatorname{Var}(u_i)+\epsilon}},
$$

再把发送节点 $r$ 的效用加入所有接收节点和注意力头：

$$
\widetilde e_{i,jr}^{(h)}
=
e_{i,jr}^{(h)}
+\lambda_u\operatorname{sg}(\widehat u_{ir}).
$$

$$
\widetilde A_{i,jr}^{(h)}
=
\operatorname{softmax}_r
\left(\widetilde e_{i,jr}^{(h)}\right).
$$

这样 query 不仅决定“检索哪些 support”，还会决定“哪些 support 更有资格向
其他节点发送消息”。默认 $\lambda_u=0.5$。

### 2.3 DUA-Pool 与 Soft Adaptive-K

消息传播后的节点为 $H_{ij}$。最终不再统一使用 $1/K$：

$$
\pi_{ij}
=
\operatorname{softmax}_j
\left(\frac{\operatorname{sg}(u_{ij})}{\tau_p}\right),
$$

$$
p_i
=
\operatorname{Norm}
\left(\sum_{j=1}^{K}\pi_{ij}H_{ij}\right).
$$

默认 $\tau_p=0.1$。有效 support 数记录为：

$$
K_{\mathrm{eff},i}
=
\frac{1}{\sum_j\pi_{ij}^2}.
$$

因此代码仍保持固定 $K=5$ 的稳定张量形状，但不同 query 可以形成不同的
有效 support 数，不再启用旧的离散/prefix Adaptive-K。

## 3. 四种严格可切换模式

| 参数 | 消息传递 | 最终池化 | 用途 |
|---|---|---|---|
| `mean` | 原 self-attention | mean | 原 GraphRefiner 等价路径 |
| `dua_pool` | 原 self-attention | DUA | 单独检查池化 |
| `qdmp_mean` | QDMP | mean | 单独检查消息传播 |
| `tugr_full` | QDMP | DUA | 默认完整模型 |

虽然第一次复现直接运行 `tugr_full`，这些开关已预先保留，后续补论文消融
不需要再次修改代码。

## 4. 关键文件改动

### `co_train.py`

- 重构 `GraphRefiner`，实现 DUA、QDMP、DUA-Pool 和四模式开关；
- 保留并冻结原先声明但未参与前向的 `edge_nn`，维持随机初始化顺序与
  state layout，同时不再把无梯度参数交给优化器；
- 统一创建两个方向的 GraphRefiner 和 Memory；
- 梯度有限性检查与裁剪覆盖优化器中的全部参数，包括 GraphRefiner；
- 分开记录 i2t、t2i 无监督损失，修复原来后一个方向覆盖前一个方向日志的问题；
- 新增 pooling/message entropy、top-1 weight、utility 和有效 K 诊断；
- 新增严格的 epoch 边界恢复训练；
- 新增 `co_train_epochs`，可在 `num_epochs=40` 的余弦调度尺度下准确运行
  20 个 co-training epoch，不再依赖外部进程强制终止。

### `memory_bank.py`

- 将当前 query 与选出的 support 一起传入 GraphRefiner；
- support 检索仍然不反向传播，GraphRefiner 后续路径仍然可微；
- Memory 状态升级为紧凑 schema 2，只保存有效槽位而不是全部空容量；
- 仍可读取旧 schema 1 状态。

### `run.py`

新增：

- `--refiner_mode`；
- `--refiner_heads`；
- `--refiner_dropout`；
- `--refiner_utility_temperature`；
- `--refiner_pool_temperature`；
- `--refiner_message_prior_strength`；
- `--refiner_end_to_end_utility`；
- `--refiner_eps`；
- `--resume`；
- `--co_train_epochs`。

所有温度、强度、维度和取值范围均在启动时验证。

### `utils.py`

checkpoint 先写入同目录临时文件，再使用原子替换生成最终文件，降低写盘中断
造成半截 checkpoint 的风险。

## 5. Checkpoint 规则

每个 epoch 保存：

1. `checkpoint_<epoch>.pth.tar`：编码器、GraphRefiner 和实验配置；
2. `model_best.pth.tar`：正常 Test 使用；
3. `resume_latest.pth.tar`：只保留一个完整恢复点。

完整恢复点包含：

- Model A/B 编码器；
- A/B 各自的 i2t/t2i GraphRefiner；
- A/B Memory；
- 两个 Adam 状态；
- 历史 GMM loss；
- best rSum 与 next epoch；
- Python、NumPy、PyTorch 与 CUDA RNG 状态。

恢复时会核对数据集、噪声率、seed、batch size、优化设置、Memory 设置和
GraphRefiner 设置。允许把 `co_train_epochs=20` 改成 40，从 epoch 20 继续，
但不允许在恢复过程中偷偷改变核心方法。
